# WA 插件审核清单

先按严重程度报告具体问题。每个问题应给出文件和行号，并说明实际运行或用户行为影响。问题判断以实际影响、接口文档或运行时源码为依据。

## 接口与结构

- 回调、`info.prop` 字段、全局变量和接口均能在 WA 文档或运行时源码中找到依据。
- `info.prop` 包含 `name`、`author`、`version` 和有效的 `YYYYMMDD` 格式 `updateTime`。
- `main.java` 使用 WA 的 BeanShell 顶层脚本结构。
- 代码较多时，`main.java` 只负责加载顺序、回调、需要共享的 Hook 或任务引用，以及调用对应的功能模块。
- `src` 文件名优先使用 `Config.java`、`Service.java` 等用途明确的短名；存在多个同类模块或容易混淆时，再增加必要的业务限定词。
- 代码中每个 `loadJava` 路径都指向插件目录内的真实文件，文件名大小写正确，并在调用相关代码前加载。
- 文件和流使用 WA 当前运行时兼容的普通 `try/catch/finally`，并在 `finally` 中明确调用 `close()`。
- 模块之间没有循环依赖，同一个模块不会被重复加载。

## 回调行为

- 消息方向判断符合功能。入站自动处理通常以 `if (msgInfoBean.isSend()) return;` 开始。
- 消息回调使用 `msgInfoBean.getTalker()` 取得事件会话；当前会话主动操作使用 `getTargetTalker()`。
- 读取某类消息独有的字段前已经判断消息类型或会话类型。
- `onClickSendBtn` 仅在插件确实需要拦截本次发送时返回 `true`。
- 菜单创建回调只注册菜单项；发消息、写配置等实际操作位于点击 lambda 内。

## 群聊与联系人

- 好友 ID 和群聊 ID 分别从对应集合赋给独立变量。
- `groupCount` 由已选群聊集合计算。
- 插件自有变量统一使用 `groupWxid`、`groupWxids`、`selectedGroupWxids`、`groupCount` 等明确命名。只有复述接口签名时保留文档中的参数名。
- 同时存在多个 ID 或数量时，先赋给含义明确的变量，再传入对应接口参数。
- `addChatroomMember` 或 `inviteChatroomMember` 可能需要审核时使用带 `reason` 的重载。`reason` 表示邀请者提交给群主或管理员的入群申请理由。

## 异步、生命周期与安全

- `get`、`post`、`download` 的结果只在回调中使用，并在可能失败时判断 `null`。
- 异步回调使用发起操作时保存的会话作为发送目标。
- Hook、广播、定时任务、观察者和其他注册项都在 `onUnload()` 中进行对应清理。
- 插件重载后，同一个 Hook、广播或定时任务不能重复注册；保存的引用应指向当前生效的注册项。
- 凭据、Token、私有地址和用户敏感数据放在配置中，不写死在源码里，也不直接输出到日志。
- 错误反馈包含定位问题所需信息，敏感内容经过脱敏，重复提示具有频率限制。

## 行为验证

- 覆盖符合条件与不符合条件的消息或会话。
- 涉及联系人选择时，覆盖空选择、好友与群聊混合选择、多个群聊选择。
- 涉及群邀请时，覆盖需要管理员审核的场景，并确认提交的是邀请申请理由。
- 涉及 Hook 或反射时，说明 WA/微信版本假设以及未覆盖的运行风险。
